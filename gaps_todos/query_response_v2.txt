$N=2$ (i.e. $A\ \text{Collapse}\ A$, then UnCollapse one $A$ back out): one of the two identical entries is removed, leaving $N=1$ — and an $N=1$ atom holding exactly $A$'s own $(r,\hat n,\chi)$ *is* $A$. So $=A$ is correct here, but it's correct because $2-1=1$, not because of some general property of UnCollapse.

$N=3$ (three copies of $A$ collapsed together): removing one copy should leave $N=2$, not $N=1$ — an atom still holding two remaining copies of $A$, which is a genuine Collapse-shaped object with $N=2$, not bare $A$ itself. Setting this equal to "$A$" would mean two real, still-present contributions quietly vanished along with the one actually removed.

## The general rule, stated precisely

UnCollapse removes exactly one contribution, so $N\to N-1$, every time, uniformly. "$=A$" isn't UnCollapse's general behavior — it's the specific coincidence that happens only when the starting $N$ was $2$, because that's the one case where $N-1$ lands on $1$. For any $N>2$, one application of $A\ \text{UnCollapse}\ A$ still returns a Collapse-type object, just with its count reduced by one, not collapsed all the way back to a bare atom.

## Why this matters, and it's the same shape of reason as last message

This is exactly the $T$-path analogy holding up a second time: a path visiting an actor three times, with one visit undone, still visits it twice — it doesn't drop to zero visits in one step. UnCollapse removing one contribution at a time, regardless of how many remain, is the same discipline applied to Collapse that the paper already applies to $T$. "$=A$ for all $N>1$" would mean UnCollapse behaves like a full reset rather than a genuine, count-respecting removal — which would undercut the very property (preserving multiplicity) that's been the whole reason Collapse and Bundle needed to stay two different verbs.

So: $N\to N-1$ as the actual rule, with "$=A$" correctly describing only the single case where that arithmetic terminates at $N=1$ — not a property of UnCollapse for every $N$ above it.

## One distinction worth keeping visible going forward

$N$ (how many *distinct* entries) and $n_i$ (how many times *this* entry was contributed) are now two different things, and total evidence is $\sum n_i$, not $N$ — worth not conflating them later. And this is deliberately a different mechanism from ids, not a replacement: $n_i$ answers "how many," cheaply, compressed, no identity tracking. ids answer "which specific one," when two contributions share a value but came from genuinely separate sources needing individual recovery. Count for confidence, id for provenance — both can sit on the same $v_i$ without conflict, used only when each is actually needed.
